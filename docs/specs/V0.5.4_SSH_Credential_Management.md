# VCL SSH Credential Management — SPEC v0.1

**状态：** Draft  
**适用范围：** VCL Controller / `vcl-fleet`  
**目标：** 简化 SSH 凭据管理，消除多密钥环境下的 `AUTH_LIMIT` 问题。  
**落盘日期：** 2026-11-02  
**目标版本：** 0.5.4（待确认；若改到 0.6.x 只重命名本文档）

## 1. 目的

重新设计 VCL Controller 的 SSH 凭据管理机制，采用两种明确的凭据模式：

1. **Agent（默认、优先支持）**：使用 SSH Agent 中已加载的私钥，通过公钥指纹精确选择身份。
2. **Identity File**：使用指定路径的 SSH 私钥文件，适用于自动化及不使用 SSH Agent 的环境。

彻底移除 `openssh-default` 模式，不再允许 OpenSSH 隐式遍历本机全部可用密钥。

**设计原则：VCL 只负责选择凭据，不负责托管私钥。**

## 2. 凭据模式

### 2.1 Agent 模式（默认）

- 从 SSH Agent 枚举已加载的公钥及 SHA256 指纹。
- 用户选择一把密钥，绑定到命名 Credential Ref。
- Controller 仅保存公钥、指纹和凭据引用，不保存私钥。
- 连接时通过指定公钥和 `IdentitiesOnly=yes`，精确使用 Agent 中匹配的身份。
- 如果 Agent 不可用或指定密钥未加载，直接返回明确错误。
- 禁止自动尝试其他 Agent 密钥。

兼容现有 `pass show ... | ssh-add -` 工作流，无需修改私钥的存储方式。

### 2.2 Identity File 模式

- 用户指定本地 SSH 私钥文件路径。
- Controller 保存路径引用，不复制私钥。
- 连接时通过 `-i` 和 `IdentitiesOnly=yes` 指定身份。
- 可以使用 SSH Agent 解锁对应的加密私钥，但不得尝试其他身份。
- 文件不存在或无法访问时直接报错。

两种模式均须采用确定性身份选择，不允许静默回退到另一种模式。

## 3. 凭据数据模型

示例：

```json
{
  "schema_version": 2,
  "bindings": {
    "hk-admin": {
      "type": "agent",
      "fingerprint": "SHA256:EXAMPLE",
      "public_key_file": "keys/hk-admin.pub"
    },
    "us-admin": {
      "type": "identity_file",
      "path": "/home/user/.ssh/us_admin"
    }
  }
}
```

约束：

- Credential Ref 为凭据的稳定标识。
- 多个节点可以引用同一 Credential Ref。
- 每个节点支持独立指定 Admin 与 Observe 凭据。
- Portable Workspace 只保存凭据引用关系。
- 公钥、指纹与私钥路径属于 Controller 的 Machine-local 配置。
- 私钥内容、Agent Socket 不得进入 Workspace、审计日志或备份。

## 4. 核心操作流程

### 4.1 凭据注册

1. 用户选择 Agent 或 Identity File。
2. Agent 模式下列出当前已加载的密钥供选择；Identity File 模式下选择文件。
3. Controller 验证凭据有效性。
4. 创建 Credential Ref 并保存本机绑定。

### 4.2 节点绑定

1. 选择目标节点。
2. 为 Admin / Observe 分别选择 Credential Ref。
3. 保存节点与凭据之间的引用关系。
4. 可选执行 SSH 连通性验证。

更换节点凭据不得修改其他节点的绑定，也不得意外覆盖共享的默认凭据。

### 4.3 SSH 连接

```text
Node
  ↓
Resolve Credential Ref
  ↓
Agent / Identity File
  ↓
Validate Identity
  ↓
Build SSH/SCP Arguments
  ↓
Connect
  ↓
Report Result
```

所有 SSH、SCP、Provision、Upgrade、Sync 和其他远程管理操作必须共享相同的凭据解析机制。

### 4.4 旧配置迁移

- 已明确绑定私钥文件的节点迁移为 `identity_file`。
- 原 `openssh-default` 或未指定身份的节点标记为 `CREDENTIAL_MIGRATION_REQUIRED`。
- 提供交互式迁移流程，优先推荐 Agent 模式。
- 禁止在迁移过程中自动猜测或选择 Agent 密钥。
- 未完成迁移的节点不得静默恢复旧的全密钥遍历行为。

## 5. CLI 功能

保留现有 `access` 和 `node` 命令层级，仅扩展必要功能。

```bash
# 列出 SSH Agent 中的密钥
vcl-fleet access agent list

# 从 Agent 绑定密钥
vcl-fleet access bind hk-admin --agent

# 绑定私钥文件
vcl-fleet access bind us-admin \
  --identity-file ~/.ssh/us_admin

# 节点指定凭据
vcl-fleet node set hk01 \
  --admin-credential-ref hk-admin \
  --observe-credential-ref hk-admin

# 检查凭据状态
vcl-fleet access verify
```

以上为拟议命令，具体参数可在实现阶段调整。

Agent 绑定命令应支持交互选择及非交互式指纹指定，便于人工和 Agent 分别调用。

## 6. 错误处理

| 错误码 | 含义 |
|---|---|
| `CREDENTIAL_UNBOUND` | 凭据引用未绑定 |
| `AGENT_UNAVAILABLE` | SSH Agent 无法访问 |
| `AGENT_KEY_MISSING` | 指定密钥未加载 |
| `IDENTITY_FILE_MISSING` | 指定私钥文件不存在 |
| `AUTH_FAILED` | 指定身份认证失败 |
| `AUTH_LIMIT` | 服务器认证次数上限已触发 |

错误信息必须可供 Agent 解析，并提供明确的人工修复建议。

禁止通过轮流尝试其他私钥来自动恢复认证失败。

## 7. 安全与兼容性约束

- 必须保留现有 SSH Host Key Trust 验证。
- 不得禁用 `StrictHostKeyChecking`。
- 必须检查 SSH Config 中额外 `IdentityFile` 引入的身份，确保实际候选密钥受到限制。
- 凭据切换不得影响 VCL 的用户身份、REALITY 密钥或代理连接配置。
- 不增加公网管理 API。
- 不实现新的私钥加密存储系统。
- Windows 和 Linux OpenSSH 均须通过兼容性测试。

## 8. 验收标准

- [ ] Agent 加载超过 10 把密钥时，指定身份能够正常连接。
- [ ] Agent 模式无需本地私钥文件。
- [ ] Identity File 模式能够正常使用指定私钥。
- [ ] 两种模式都不会尝试无关密钥。
- [ ] 多节点可安全共享同一 Credential Ref。
- [ ] 修改单节点凭据不会影响其他节点。
- [ ] SSH 与 SCP 的身份选择行为一致。
- [ ] 缺失凭据时返回明确错误，不进行隐式回退。
- [ ] 旧配置可通过显式迁移转换为两种新模式。
- [ ] Host Key 验证及原有安全边界不受影响。

---

## 9. 非目标

本版本不实现：

- SSH 私钥加密托管。
- `pass` / GPG 数据库管理。
- SSH Agent 自动启动或自动加载私钥。
- SSH 密钥自动生成、轮换或分发。
- 多身份循环尝试及自动认证回退。
- 新的凭据管理 WebUI。

**最终目标：让 VCL 明确知道每个节点应该使用哪把 SSH 密钥，同时继续使用用户现有的 SSH Agent 或本地私钥管理工作流。**

## 10. 实现备注（2026-11-02 决策）

- **版本**：Controller `0.5.4` / Node `0.5.3`；Node payload 与最低兼容 Node 不变。
- **绑定文件**：`CONFIG/vincula/controllers/<fleet_id>/credential-bindings.json`，schema_version 升级到 2；Agent 公钥落在同目录的 `keys/<ref>.pub`，绑定里存相对路径，私钥与 Agent Socket 均不落盘到 Workspace/备份。
- **严格 SSH Config 隔离**：VCL 连接统一加 `-F <os.devnull>`（Linux `/dev/null`，Windows `NUL`），只使用显式 `-i` 与 Agent 中匹配的公钥；因此 `~/.ssh/config` 的 `ProxyJump`/`ProxyCommand`/自定义 Host 别名不会生效。Host Key 仍由 VCL 的 `trust/known_hosts` + `StrictHostKeyChecking=yes` 或系统默认 known_hosts 校验。
- **v1 迁移**：v1 `identity_file` 读取时按 v2 语义使用（确定性、无遍历）；v1 `openssh-default` 转为 `migration_required`，不再尝试连接。`access migrate` 负责把两种旧状态写成显式 v2 绑定；迁移不自动选择密钥。
- **错误与状态**：连接前解析凭据，错误码写入 `ssh_reason`/`access verify --json`；节点另暴露 `credential_state`（`OK` / `CREDENTIAL_MIGRATION_REQUIRED` / `CREDENTIAL_UNBOUND` / `AGENT_UNAVAILABLE` / `AGENT_KEY_MISSING` / `IDENTITY_FILE_MISSING`）。
- **兼容入口**：保留 `node set --identity-file` 作为单节点换钥（copy-on-write），新增 `--admin-credential-ref`；`--openssh-default` 删除。Agent 绑定支持 `--fingerprint` 非交互与 TTY 数字选择。
