## Goal

**0.4.4 initial / day-to-day UI v2 surface** per rev1 §16 (not a claim of every §16 drawer detail): six pages, Overview KPIs / trends, Nodes / Users / Traffic / Audit enrichment, UI-triggered Operations history, and **Command Builder** (no identity mutations). See SUMMARY for PARTIAL gaps (instance history UI, user destinations, full CLI ops history).

| In | Out |
| --- | --- |
| Overview: health, counts, traffic today, last sync, cache age, trend, top users/hosts, recent problems | UI identity mutations |
| Nodes: users / traffic today / endpoint; detail users + last operations | Rendering VLESS URI / credential UUID / Reality key / Clash secret |
| Users: department, enabled state, today / 30D | Running provision/adopt/rotate from UI |
| Traffic: node/user/department/destination filters, **filtered** trend, upload/download | Probe rewriting last-status.json |
| Audit: destination IP / port / network filters (SQL before LIMIT) | |
| Command Builder: fill fields → shell-safe CLI (`shlex.join`) | |
| Probe live overlay; Sync = `sync --full` | |
| users-cache under `ui-runtime/` (legacy Fleet Home migrated + deleted) | |

## Non-negotiables (inherit AC-3.1)

1. Loopback-only bind.
2. `identity_mutations: false`; mutate POST → **405**.
3. `reseed` CLI-only.
4. No secrets / credential UUID in default JSON / pages (`has_active_credential` bool / unknown only).
5. Closing UI does not affect VPS nodes.
6. Probe does not write `last-status.json`.
7. Workspace GET never mkdir / migrate view.

## Known gaps vs full rev1 §16 (documented PARTIAL)

- Node Detail API may include instance history / recent usage; UI drawer does not yet render those tables.
- User Detail lacks destinations list.
- Operations page records **UI-triggered** actions only (not full CLI provision/adopt/replace/user.add/rotate/backup/restore history).
