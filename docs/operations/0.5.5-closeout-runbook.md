## Data and migration

Node and Controller are 0.5.5, accounting/fleet-cache are schema 5. Existing
supported Node versions including 0.5.3 use the typed upgrade path. Old nodes
are unsupported for normal Observation; discovery retains their actual version,
and explicit identity/upgrade/recovery paths remain for one-time ingress; do not rewrite prerelease
version strings to bypass the allowlist. Re-running an installer of the same
version verifies state; it does not change port, SNI or advertised endpoint.

Before a migration, identify the real paths and writers, stop the sole Node
collector or hold the Controller operation lock, inspect free space, and create
a consistent verified backup. The converter keeps a private `*.pre-v5-*.db`
SQLite backup next to the database and validates a separate candidate before
activation. Reserve three database sizes plus 512 MiB for migration. Do not
delete backups as part of normal import or startup.

Node/Controller normal writer startup performs the supported migration; query
commands do not. Unknown/future schema, bad timezone-less timestamps, corruption,
insufficient reserve or a changed source refuse activation. Preserve the
original failure and backup, correct the prerequisite and retry deliberately.

Timestamps are canonical UTC with six fractional digits. Whole-connection bytes
belong to the UTC start day, not to each wall-clock day of transmission. It is
still approximate Clash polling, not billing. Daily aggregates now survive raw
pruning and expire only under their own configured retention. Existing explicit
retention values remain unchanged.

The old daily rows are retained as `legacy_daily_usage`, separate from verified
raw-reconstructed totals. `history_coverage` explains unverified legacy data and
the absence of recovery for already deleted history. Do not add legacy totals
to current totals: overlap and timezone assignment may be unverifiable.
This also applies to nodes whose raw table is now empty: their old daily rows
remain only in the legacy snapshot. `history-coverage/v1` identifies the snapshot
time, raw/legacy interval envelopes and known prune sequence. An interval envelope
does not assert continuous collection; `completeness=NOT_PROVEN` and
`missing_history_recovered=false` remain explicit. A raw-prune marker does not
prove that pre-v5 daily history survived. Node and Controller packages ship the
versioned contract; exports keep audit-export/v2 identity/paging unchanged.

On failure before activation, the source remains the active database. Before
rollback after new writes, stop the writer and preserve the new schema-5 database
too. Restoring the old checkpoint does not include those new writes; never
describe that operation as lossless. Restore/reissue still has its documented
credential rotation semantics; ordinary upgrade preserves existing profiles.

## Local cache policy

`vcl-fleet cache status --json` is read-only, including absent/old/corrupt caches.
It reports `cache-status/v1`, physical/auxiliary bytes, free space, effective
policy, import permission and history coverage. Errors are local cache facts,
not Node Health failures. An absent cache is not created by the command.

Policy lives in CONFIG `vincula/controllers/<fleet_id>/cache-policy.json`, beside
machine-local bindings; legacy mode uses its machine-local directory. It is not
part of portable Workspace or its exports. Default configuration:

```json
{"schema_version":1,"max_bytes":8589934592,"warning_fraction":0.8,"min_free_bytes":536870912}
```

The 8 GiB limit applies to the main database; WAL/journal bytes are also reported.
Before a new transaction, conservatively reserve up to the current database size
for rollback journaling in addition to the 512 MiB floor. `required_free_bytes`
and `journal_reserve_bytes` explain a refusal before the base database is full.
An already allocated transaction journal is not reserved a second time at commit.

At 80% inspect growth and prepare an operator-owned archive/maintenance plan. At
the limit, `CACHE_LIMIT_REACHED` refuses the new page/transaction; low free space
uses `DISK_SPACE_LOW`. Sync returns PARTIAL/exit 2 with structured node rows and
does not advance the refused page's cursor. Earlier committed pages and existing
history remain intact. Archive restore uses the same guard.

Do not reset/reseed to recover capacity. Verify an existing audit archive and
retain a full consistent backup before considering any manual cleanup. Automatic
archive/pruning/compaction is deferred to 0.6.4. An operator may explicitly revise
the local limit after checking disk and backup capacity; the program never
increases it or deletes history automatically. Reads remain available over limit.

## Credentials and restore inputs

New Agent selectors are content-addressed and machine-local. Old selector paths
remain readable. A missing/mismatched selector fails closed; explicitly rebind the
intended ref/fingerprint through the normal access workflow. Never edit a public
selector to make its fingerprint check pass, or guess another identity.
`access migrate --selectors [--node NAME] [--purpose admin|observe|both] [--json]`
explicitly rewrites valid old selector paths without SSH or selecting another key.
All old fingerprints are checked before bindings publication; failed publication
keeps the old binding file intact.

`node replace --observe-credential-ref REF` is explicit authorization selection
for the new endpoint. Without it, the command reports observation as
NOT_CONFIGURED and provides remediation; restore the observer's actual key/user
authorization and set its ref before monitoring. Old endpoint authorization is
not silently reused.

Internal render/authentication helpers transfer arguments through anonymous
descriptors. Backup helper plaintext `--new-reality-private` and
`--new-clash-secret` options are rejected without value echo. Use their `-file`
or `-fd` alternatives; files must be owned private regular files, descriptors >=3.
The managed restore wrapper passes generated keys by fd. Keep credentials in the
operator's private terminal/files, never chat, command arguments or evidence.

## Live/H05 execution boundary

Prepare exact target aliases, operator/window, backup/readback, fault/recovery
steps and stop criteria before requesting a production window. Start with
read-only baseline and one recoverable canary. Use only actual required one-time ingress
samples. Measure their upgrade/recovery paths and <=3s new-connection
unavailability; do not infer an upper bound from coarse polling alone.

The approved H05 scale is seven real 0.5.5 nodes plus at least ten simulated
nodes for two hours. Record this accepted scope deviation in the final signoff.
A new immutable RC must run >=24h continuously, with dedicated real proxy probes
and inspect-capable Node data. Include observer permission/revocation, accountd
identity, proxy/accounting separation, SSH/Controller outage recovery, Finding,
drift/restoration and zero unintended Node writes/restarts on read-only checks.

H05-01..08 results and the human signature remain empty until performed. The old
26h33m run is retained with its old candidate, missing proxy/inspect dimensions
and two authentication failures. It supplements the new run and is not relabelled.

For an abandoned runtime-only replacement, preserve its install manifest and
backups and use the documented restore/retry path. General automatic runtime-only
uninstall is deferred; do not recursively remove guessed system paths.
