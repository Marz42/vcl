## 一、版本定位

0.5.0 是 **Observation Plane** 的首个可发布里程碑，建立机器可读的 Node 能力发现与遥测快照，在 Controller 侧引入 observe/admin credential 路由语义，并提供 **Controller 编排的 Node 固件原地升级**（0.3.1+ → 当前最新 Node 制品）。

**本版本回答：**

- Node 是否可达、运行多久、资源占用如何？
- sing-box / accountd 是否在运行？
- accounting 管道是否还在推进（poll age / export_seq）？
- 如何把生产 Node 从 0.3.x 升级到 0.5.x 且 **不断 URI、不断服务语义**（允许秒级断流）？

**本版本不负责：**

- 自动修复、改配置（升级除外）；
- 持续监控 daemon（→ 0.5.1）；
- Finding / 异常检测（→ 0.5.2）；
- inspect / drift / verify 强化（→ 0.5.3）；
- Desired State / Reconciliation（→ 0.6.0）。

长期关系见 Master SPEC §1：0.5.x 从 Fleet Manager 跃迁为 **Observable Fleet**，0.5.0 只铺 **事实层基础**。

## 三、Node 原地升级（Firmware Update）

0.5.0 引入 **typed、可审计、可回滚** 的 Node 固件升级，使 Fleet 能把 0.3.1+ 节点升级到 Controller 内嵌的最新 Node payload（初始为 **0.5.0**），而无需 replace 或 re-provision。

> 完整 upgrade plan/apply/rollback 状态机、fleet 级编排与 maintenance window 在 **0.6.4** 扩展；0.5.0 交付 **单节点、显式批准** 的最小可用路径。

### 3.1 Controller CLI

```bash
vcl-fleet node upgrade plan NODE
vcl-fleet node upgrade apply NODE [--yes]
```

- `plan`：只读；输出 current/target version、allowlist 结果、preconditions、预期断流窗口、是否需 backup、rollback 摘要。
- `apply`：typed mutation；MUST 经 admin credential；默认需显式 `--yes`（或等价确认）。
- MUST NOT 提供 generic `exec NODE shell` 或任意远程 bash。

### 3.2 支持路径（allowlist）

初始 allowlist（可随 0.5.x patch 扩展，不得 skip major）：

| Source | Target | 备注 |
| --- | --- | --- |
| 0.3.1 | 0.5.0 | 生产存量主路径 |
| 0.3.2 | 0.5.0 | legacy seed / 新装 0.3.2 |
| 0.5.0 | 0.5.x patch | 同 minor 内 patch（实现时定义） |

- 不支持降级；不支持跨未声明版本 jump。
- 与现有 `vincula.sh` migrate 语义一致：复用 `is_supported_upgrade_from` 扩展，而非 parallel 升级逻辑。

### 3.3 Apply 流程

```text
preflight（版本、磁盘、服务健康、端口占用）
  → backup（remote `vcl backup create`，默认 secretless；可 `--include-secrets` 由 operator 显式选择）
  → stage payload（Controller 内嵌 node tarball + digest 校验）
  → migrate（remote `vincula.sh` / 等价 typed entry；沿用 EXIT trap rollback）
  → sing-box / accountd health gate
  → `vcl verify --json` + `vcl capabilities --json`
  → commit（写 VERSION；operation journal）
```

失败 MUST：

- 恢复 backup 或 migrate 内置 rollback 可达的最后已知好状态；
- 记录 `FAILED` / `ROLLED_BACK` / `PARTIAL`；
- 不得残留 half-applied VERSION 且服务不可预测。

### 3.4 服务连续性与断流预算

升级 MUST 以 **最小化 data plane 中断** 为设计目标：

| 指标 | 要求 |
| --- | --- |
| 目标断流 | **≤ 3 秒**（新 TCP 连接恢复可用）；理想 **亚秒** |
| 测量 | Live 记录 upgrade 窗口内连续 probe 失败时长（见 Live **L2**） |
| sing-box | SHOULD 优先 `reload`/最小 restart 窗口；full stop/start 仅当 migrate 必需 |
| 现有长连接 | MAY 在 sing-box 重启时断开；MUST 文档化；客户端自动重连应在秒级恢复 |
| accountd | 允许短暂停；恢复后 accounting 连续，export_seq 单调 |

**禁止：**

- 为升级改变 URI、UUID、Reality 参数或 listen port；
- 升级失败后 silent 留在不可验证状态；
- 升级过程访问公网（除既有 sing-box 数据面外）。

### 3.5 Node 侧

- 继续以 `vincula.sh` migrate 为 authoritative 原地升级实现；Controller 只编排 artifact 投递与 typed remote invoke。
- 升级完成后 Node MUST 暴露 `capabilities/v1` + `telemetry/v1`。
- 升级 MUST NOT 新增公网 management listener。

### 3.6 与 observation 的关系

- `plan` 为 read-only，MAY 使用 observe credential（若已配置）。
- `apply` MUST 使用 admin credential。
- 升级本身不是 observation 的“隐式修复”；是 **显式 typed operation**，进入 operation journal。

## 五、Node — Capability Discovery

### 5.1 命令

```bash
vcl capabilities --json
```

### 5.2 合同

- Schema：`capabilities/v1`（冻结于 [`schemas/capabilities/v1.schema.json`](../../schemas/capabilities/v1.schema.json)）。
- 返回 Node 版本与 capability 字符串列表，例如：

```json
{
  "schema": "capabilities/v1",
  "node_version": "0.5.0",
  "capabilities": ["telemetry/v1"]
}
```

- Node 0.5.0 MUST 至少声明 `telemetry/v1`。
- `health/v1`、`inspect/v1` 在后续 0.5.x 子版本添加；0.5.0 Node MUST NOT 声明尚未实现的 capability。
- 响应 MUST NOT 含 URI、UUID、Reality key、Clash secret、SOCKS/SSH 凭据。
- 响应 SHOULD ≤ **4 KiB**；超过 MUST 由 Controller 拒绝（fail closed）。
- 命令 MUST 严格 read-only：不得写配置、不得重启服务、不得访问公网。

### 5.3 Controller 消费语义

- 未知 capability 字符串 MUST 被 **忽略** 但 **原样保留** 于内部缓存（供未来版本使用）。
- 请求 `telemetry/v1` 但 Node 未声明 → 结果 **`UNSUPPORTED`**，不是 `ERROR`。
- SSH 失败、JSON 解析失败、schema 校验失败、oversize → **`ERROR`** 或 **`AUTH_FAILED`**（见 §7.2），不得 silent fallback。

## 六、Node — Telemetry v1

### 6.1 命令

```bash
vcl telemetry snapshot --json
```

### 6.2 最小字段

Schema 冻结于 [`schemas/telemetry/v1.schema.json`](../../schemas/telemetry/v1.schema.json)。

| 字段 | 说明 |
| --- | --- |
| `schema` | 固定 `telemetry/v1` |
| `node_id` | 逻辑节点 UUID |
| `instance_id` | 物理实例 UUID |
| `observed_at` | UTC ISO8601 |
| `uptime_seconds` | 自 boot 起秒数 |
| `load.load1/5/15` | `/proc/loadavg` |
| `memory.total_bytes` / `used_bytes` | 主存 |
| `filesystem` | 根分区 `total_bytes` / `used_bytes`（或等价主数据分区） |
| `network.rx_bytes` / `tx_bytes` | 累计计数（首选全局或默认出口；须在实现中固定语义并文档化） |
| `sing_box.active` | systemd active |
| `sing_box.connection_count` | 可空；来自 Clash API 或等价只读源 |
| `sing_box.restart_count` / `last_restart_at` | 可空；来自 systemd 属性 |
| `accountd.active` | systemd active |
| `accountd.last_poll_age_seconds` | 可空 |
| `accountd.export_seq` | 可空 |
| `accountd.last_event_age_seconds` | 可空 |

### 6.3 约束

- MUST NOT 访问公网、执行 package update、扫描完整 journal、做昂贵磁盘扫描。
- 响应 SHOULD ≤ **64 KiB**；超过 MUST fail closed。
- 单次调用 SHOULD 在普通低配 VPS 上 **p95 ≤ 2s**（Live 验证）。
- MUST NOT 输出 secret（含 UUID 以外的凭据、URI、私钥、Clash token）。
- MUST 严格 read-only（INV-06、INV-12）。

## 七、Controller — Observation Credential Routing

### 7.1 语义

Workspace / registry 已预留：

```text
admin_credential_ref
observe_credential_ref
```

0.5.0 起 **runtime 必须分离**（关闭 0.4 的 observe=admin 默认，D57 落地）：

| 操作类 | 凭据 |
| --- | --- |
| `capabilities`、`telemetry snapshot`、`status`、`verify`（只读 probe） | `observe_credential_ref`（若配置） |
| provision、user add、replace、sync export 等 mutation | `admin_credential_ref` |

### 7.2 规则

- 配置 `observe_credential_ref` 后，observation MUST 使用 observe route。
- observe auth failure → **`AUTH_FAILED`**；MUST NOT silent fallback 到 admin。
- mutation MUST NOT 使用 observe identity。
- 日志 / operation journal 只记录 **credential class**（`observe` / `admin`），不记录 key material。
- 未配置 observe 时，MAY 在 SPEC/CHANGELOG 中声明过渡期：仅当 observe 与 admin **显式相同 ref** 时允许共用；不得隐式把 admin 当 observe 用。

### 7.3 CLI / UI

- `vcl-fleet` 新增或扩展只读命令（名称可在实现中定为 `telemetry` / `capabilities` 子命令），经 **service layer** 调用，禁止在 CLI handler 内堆 SSH 细节。
- WebUI **不得**因 HTTP GET 触发 telemetry SSH（与 D58 cache-only 一致）；0.5.0 UI 可不展示 telemetry，但架构须预留 cache 路径。

## 八、Node — Restricted Observer Identity

Node SHOULD 支持独立 **observer** 系统用户：

- no sudo；no PTY；no agent/port/X11 forwarding；
- 仅可调用 approved read-only command（`capabilities`、`telemetry snapshot`、`identity`、`status` 等）。

**渐进交付：**

- 若 0.5.0 无法完成 forced-command / `authorized_keys` 限制，允许在 **0.5.x 内** 完成，但 MUST：
  1. 在 `docs/evidence/0.5.0/SECURITY.md` 记录 **documented deviation**；
  2. observe/admin **路由语义**从 0.5.0 起不得再变；
  3. Live Matrix 4（observer 被破坏 → AUTH_FAILED）仍 MUST PASS（可用等效方式验证）。

## 九、Node — Observability Hardening

必须审查并完成或记录 blocker：

| 项 | 要求 |
| --- | --- |
| accountd de-root | SHOULD 独立 `vincula-accountd` service user；若阻塞须 **documented blocker** |
| accountd 数据访问 | 只读非 secret identity mapping；不得读 Reality 私钥 / 用户 UUID 导出 |
| Clash API credential | 最小权限注入 |
| systemd | 保持 / 强化 `NoNewPrivileges`、`ProtectSystem`、`ProtectHome`、capability bounding |
| 威胁模型 | accountd compromise 不得直接获得 Node root authority |

当前基线（0.3.2）：accountd 仍 **User=root** — 0.5.0 MUST 给出明确结论（完成 de-root **或** 写入 SECURITY evidence blocker）。

## 十一、0.5.0 Live Matrix

在 [`docs/evidence/0.5.0/`](../evidence/0.5.0/SUMMARY.md) 记录。未执行项 MUST 标 **`PENDING LIVE`**。

| ID | 场景 | 期望 |
| --- | --- | --- |
| **L1** | Fresh Node 0.5.0 `telemetry snapshot` | 合法 JSON；字段齐全；无 secret；p95 体感 ≤2s |
