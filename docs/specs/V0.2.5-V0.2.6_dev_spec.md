# Vincula v0.2.5–v0.2.6 Development Plan

## 0. 总目标

两个版本分别解决两个问题：

```text
v0.2.5
User Provisioning & Lifecycle
→ 把“用户怎么创建、发放、停用、轮换”做完整

v0.2.6
Accounting UX / Analytics Hardening
→ 把“已经采集的数据怎么查询、解释、导出”做完整

```

严格禁止把以下工作混入：

```text
Reliable Accounting
非 polling backend
billing
quota / rate limit
Web UI
subscription
central fleet control
service/vendor classification
复杂 HR 历史组织模型

```

v0.2.4 当前 accounting 明确仍为 Clash API polling，短连接可能漏记，因此 v0.2.6 必须继续称为 approximate accounting。

# Part I — v0.2.5 User Provisioning & Lifecycle

## 1. 目标

管理员应能够完成：

```text
批量创建用户
↓
生成独立 credential
↓
发放 VLESS URI
↓
修改用户 metadata
↓
暂停/恢复用户
↓
轮换泄漏 credential
↓
随时重新导出链接
↓
验证 Registry / config 一致性

```

所有用户 mutation 必须保持：

```text
users.json
    ↓
generated sing-box config
    ↓
runtime

```

的一致性。

---

# 2. 身份模型必须冻结

v0.2.5 开始后以下定义视为 API contract。

## `user_id`

永久主体身份。

要求：

```text
immutable
globally unique
not reused

```

accounting 历史归属于 `user_id`。

---

## `tag`

管理员 CLI 使用的稳定、人类可读标识。

例如：

```text
alice
bob.li
sales-01

```

建议约束：

```regex
^[a-z0-9][a-z0-9._-]{0,31}$

```

v0.2.x 不支持 rename tag。

---

## `display_name`

自由显示名：

```text
Alice Zhang
张三
王小明

```

允许 Unicode，可以修改。

---

## `department`

组织 metadata。

允许 Unicode，可以修改。

不能参与 authentication identity。

---

## `credential_id`

一次 credential 实例的永久 ID。

每次 rotate 创建新的 `credential_id`。

---

## `uuid`

认证 secret。

可以 revoke / rotate。

不得作为永久 user identity。

当前 `users.json` schema 已经具备 `user_id/tag/display_name/department/credential_id/node_id/uuid/status/revoked_at` 等字段，可以以其作为 v0.2.5 基础。

# 4. `vcl user add`

示例：

```bash
vcl user add alice \
  --display-name "Alice Zhang" \
  --department Sales

```

行为：

```text
generate user_id
generate credential_id
generate UUID
create active credential
update Registry
generate candidate sing-box config
sing-box check
apply
runtime health check
commit
print URI

```

成功：

```text
Created user: alice
User ID: ...
Credential: ...
Status: active

VLESS URI:
vless://...

```

不得默认打印 UUID 以外的敏感内部信息。

---

# 5. `user disable / enable`

## Disable

```bash
vcl user disable alice

```

结果：

```json
"enabled": false

```

并重新生成 sing-box config，使该用户所有 credential 不再进入 active authentication set。

必须保持：

```text
user_id
metadata
credential history
accounting history

```

全部不变。

语义必须明确：

> disable 保证新的 authentication 失败；不保证已建立的连接立即断开。

不得通过 restart sing-box 来强制断掉全部用户。

---

## Enable

```bash
vcl user enable alice

```

重新启用其当前 active credential。

不得生成新的 UUID。

---

# 6. `user rotate`

```bash
vcl user rotate alice

```

行为：

```text
credential A:
status = revoked
revoked_at = now

credential B:
new credential_id
new UUID
status = active

```

保持：

```text
user_id unchanged
tag unchanged
display_name unchanged
department unchanged
historical accounting unchanged

```

旧链接必须无法建立新连接。

新 URI 输出给管理员。

# 9. Bulk Import 安全规则

导入必须先完成全量 validation，然后才能 mutation。

顺序：

```text
read file
↓
parse all rows
↓
validate header
↓
validate every tag
↓
detect duplicate rows
↓
detect conflicts with Registry
↓
generate IDs/UUIDs in memory
↓
candidate Registry
↓
candidate sing-box config
↓
sing-box check
↓
transaction commit

```

任何一行错误：

```text
NO users added
NO config changed
NO credentials output

```

禁止部分成功。

# 16. Registry mutation transaction

所有 mutation：

```text
add
set
disable
enable
rotate
import

```

必须使用同一 transaction pipeline。

禁止每个 command 自己实现一套 config edit。

建议抽象：

```text
load registry
↓
validate
↓
mutate candidate state
↓
render candidate config
↓
sing-box check
↓
backup current artifacts
↓
atomic install
↓
reload/restart as required
↓
health check
↓
commit

failure
↓
rollback

```

# 17. Reload strategy

Agent 必须先确认当前 sing-box config reload 行为是否安全满足 auth user 变化。

优先：

```text
reload

```

只有无法可靠应用时才：

```text
restart

```

如果 restart：

必须文档说明：

> 用户 mutation 会短暂中断所有现有连接。

不能静默发生。

# Part III — Repository / Engineering Requirements

## 40. 先解决 release tree duplication

v0.2.4 当前已记录：

```text
release/
vs
repo root

```

存在双份代码树，需要人工同步，容易发生漂移。

在 v0.2.5 开始前建议改成：

```text
repo/
├── bin/
├── lib/
├── scripts/
└── ...

        ↓ build

dist/
└── vincula-0.2.5/

```

规则：

```text
canonical source only in repo root/source tree

dist/release
= generated artifact
= never edited manually

```

例如：

```bash
scripts/build-release.sh

```

执行：

```text
copy canonical files
↓
generate release.lock
↓
archive
↓
SHA256
↓
run package verification

```

这是 v0.2.5 开发前建议完成的唯一仓库结构调整。
