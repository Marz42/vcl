# VCL 0.5.1 — Monitoring & Health

状态：G0 Frozen（2026-09-26）；本地开发交付收口，实际G1～G3结果见[本地证据](../evidence/0.5.1/SUMMARY.md)。用户于2026-09-27明确暂不执行真实VPS验收；G4/G5保留PENDING LIVE，不能宣布完整发布。上级：[Master §7.2](VCL_0.5-0.7_Master_SPEC.md)；执行：[实施方案 §4.2](../plans/VCL_0.5-0.7_Implementation_Plan.md)。

## 1. 合同与范围

- Controller 新增 `monitor [NODE] [--once] [--interval 30] [--timeout 5] [--concurrency 8] [--json]`。默认前台持续运行，Ctrl-C 停止；`--once` 执行一轮。输出不包含 SSH 原始 stderr/credential。
- `health [NODE] [--json]` 与 UI `GET /api/monitor` 严格 cache-only。未监控、过期、坏记录显示 UNKNOWN，不通过 GET 初始化或修改数据库。
- Node `telemetry/v1` 保持不变。开发版本戳 Controller/Node 均为0.5.1，最低兼容Node仍为0.3.1；缺 telemetry 为 UNSUPPORTED，不推断节点故障。Node 0.5.0 支持监控但不具备本版本硬化；typed upgrade支持0.3.1/0.3.2/0.5.0→0.5.1。现场升级/回滚未验收前不得宣布发布。
- 本地派生 contract 为 `monitor/v1`：generated_at、cache_state、nodes；每节点包含 name/node_id、received_at、telemetry_age_seconds、observation_state、四维 health、overall、数值 metrics、probe。只有 Node/instance 的非认证 UUID 可存；禁止原始用户 UUID/URI/SSH stderr/自由文本远端字段落库。

## 2. 健康与调度

四维为 node、observation、proxy、accounting；状态为 HEALTHY/SUSPECT/DEGRADED/UNREACHABLE/RECOVERING，缺少证据使用 UNKNOWN。每项包含固定 reason code 和连续成功/失败次数。一次传输失败 SUSPECT，连续三次 UNREACHABLE；恢复首次 RECOVERING，两次成功 HEALTHY。明确 service inactive 立即 DEGRADED；accountd poll age >90s 为 DEGRADED，缺 poll 信息 UNKNOWN。sing-box active 不能证明 proxy 可用，未配置真实 probe 时 Proxy UNKNOWN。

采样时间以 Controller received_at 排序；Node observed_at 超前 >30s 或超过 90s 视为陈旧，不用于判 HEALTHY。cache 超过 90s 显示 UNKNOWN，保留 last_health 供解释。网络计数按同 instance 的相邻样本计算速率；计数复位、乱序、重启不产生负速率或跨 instance 差分。

调度采用 monotonic clock，每节点一个在途任务，最多 concurrency（1～64）；默认每轮总采集 deadline 5s（涵盖 capabilities、telemetry、identity），interval 30s（1～3600）；±10% jitter；失败指数退避最高300s。任务队列最多等于注册节点数，节点上限1024；单节点异常不终止其他节点。真实 proxy probe 有独立 bounded deadline。只有显式 monitor 会写本机观测缓存；不会修改 Node 状态。

## 3. 存储与恢复

Controller machine-local `observation.db` 为独立派生缓存，与既有 `fleet.db` schema/v4 隔离，避免改写旧 cache 合同。含 telemetry_samples、telemetry_rollup_5m、telemetry_rollup_hourly、health_latest、metadata；使用 SQLite 事务、DELETE journal、private directory/file，reader `mode=ro` + query_only。

保留 raw 24h / 5m 7d / hourly 90d，并同时限制 raw 100000 行、每级 rollup 200000 行、latest 1024 节点、DB 256MiB；超过 row cap 时从最旧记录清理，metadata 记录截断，不能伪称历史完整。写入原子更新 latest/样本/rollup；重启恢复计数与状态。坏行 reader 隔离，坏 DB 明确 CACHE_CORRUPT，不隐式删除/修复；满盘、锁超时为本机缓存错误，不污染节点 Health，不影响 Node 服务。

## 4. Probe、权限与非目标

Synthetic probe 必须经独立测试身份运行 VLESS/Reality→Node→HTTPS，记录连接/TTFB/总耗时及固定失败分类。未配置、缺 runtime/credential 时 UNKNOWN，禁止用直连 HTTPS 冒充代理成功。凭据为本机私有文件，禁止加入 Workspace、argv、stdout/journal；禁止复用普通用户身份。`--probe-profiles PATH` 使用 `probe-profiles/v1` 私有本机文件，`--probe-sing-box PATH` 指向已校验的固定版本运行时。每个 profile 绑定 node_id、purpose=synthetic-probe、vcl-probe-* 专用 user_tag、server IP/port、uuid、Reality server_name/public_key/short_id、无认证信息或 query 的 HTTPS URL。profile 明确声明专用身份；实际未复用普通用户 credential 由创建流程及 Live 人工核验，不能只凭 tag 证明。POSIX 文件要求当前用户属主及0600；Windows ACL 须现场核查。运行器生成 loopback-only SOCKS inbound、唯一 VLESS outbound，无 direct fallback，退出清理临时配置和子进程；curl 忽略 curlrc/proxy 环境变量。connect_ms 表示经代理完成目标 TLS handshake 的时间，TTFB/total 从同一次请求取值。运行器 mock 测试不能当 Live probe 通过。

accountd de-root 与 observer forced-command 的安装、更新、权限迁移和回退必须一起验证；保留 SEC-050-01/02，未闭合不得声明 hardening 完成。0.5.1 不自动重启/修复，不告警发送，不 reconcile、不做 QoS/Egress。

### 4.1 accountd 最小输入与服务身份

- `accountd-runtime/v1`只保留node_id/instance_id、tag→逻辑user_id映射、Clash API端口/secret及保留期；这是受限凭据文件，不是公开telemetry。禁止复制Reality私钥、用户UUID、URI或整个规范配置。
- 固定root `ExecStartPre`生成`/etc/vincula-accountd/runtime.json`（root:accountd 0640，目录0750）；长期daemon为独立`vincula-accountd`用户，不能写该投影，也不能读`/etc/vincula`秘密文件。
- `/var/lib/vincula`只承载accounting数据，归accountd所有；prepare只处理固定数据文件，拒绝symlink/hardlink，不递归chown任意路径。规范state/users/config仍为root所有。
- 用户变更/回滚刷新投影；restore/upgrade重启时由pre-start重建投影与DB owner，不把派生Clash凭据文件加入secretless备份。旧root单元回滚不依赖新投影。
- `--runtime`禁止回退到规范secret文件或环境凭据；坏映射保留旧映射并记录固定错误，不输出原始数据。
- root pre-start是声明的权限边界，不称“所有进程完全无root”。systemd `+`仅提升该固定准备命令，daemon仍受限制：[systemd官方手册源码](https://github.com/systemd/systemd/blob/main/man/systemd.service.xml)。Python以`-I`隔离环境运行。

### 4.2 受限 observer SSH 路径

- admin显式执行`vcl observer install-key --file PUBLIC_KEY`，仅接受单个Ed25519公钥；检查独立系统用户、锁定密码、无附加组，root持有home/.ssh/authorized_keys写权限；公钥使用`restrict,command=... client`，不提供PTY/forward/sudo/shell。
- registry新增可选`observe_ssh_user`，通过`node set --observe-ssh-user`显式设置。独立用户名要求显式observe credential；capabilities/telemetry/probe/verify走observe用户名，mutation继续走admin。旧Controller不理解该字段时，不宣称完整observer兼容。
- client经本机AF_UNIX socket调用固定read-only broker，无新增公网listener。broker只接受identity/capabilities/telemetry snapshot/status/verify的固定JSON命令，校验peer UID，拒绝额外参数、shell、exec和mutation。
- broker为有界root读进程，ProtectSystem=strict、只保留DAC读取能力；每连接64MiB/16 tasks/10%单核CPU，socket最多2个并发，合计最多128MiB内存。既有helper仍要求root，因此采用进程分权，不开放sudo。request≤1KiB、输出≤64KiB、命令≤10s；默认不启用socket，显式安装key才启用。
- Live必须核对SSH daemon的effective authorized-keys/CA/外部key-command策略，确认不存在绕过forced-command的认证来源；代码白名单测试不能替代该项。
