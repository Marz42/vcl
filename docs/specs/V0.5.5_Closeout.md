## A — access and secret protection

- Agent selector names are immutable SHA256(ref + NUL + public-key blob) names;
  publish selector before bindings under a machine-local exclusive lock. A failed
  publication keeps the prior binding usable. Read old selectors compatibly;
  mismatched fingerprints fail closed. Cover case/punctuation/Unicode collisions.
- Replace accepts an explicit new observe ref. Never silently reuse the old
  endpoint's observe authorization; absent configuration is reported in JSON and
  human output with a remediation action.
- Managed render/curl/self-test/restore paths use inherited descriptors or private
  files for secrets, not argv. Reject legacy plaintext restore options without
  echoing values; provide file/descriptor alternatives.

## B — durable accounting

- Canonical connection timestamps and query bounds are UTC with six fractional
  digits. Require an explicit timezone; invalid/naive timestamps fail closed.
- Whole-connection approximate bytes belong to the UTC connection start date in
  both Node and Fleet; this is not per-day traffic slicing or billing.
- Accounting DB v5 has a per-event contribution ledger. Rollup applies only
  contribution differences in one transaction. Raw pruning finalizes contribution
  first; independent daily pruning never rebuilds retained history from raw.
- This explicitly supersedes the raw-rebuild-only restriction in the old D2
  contract. R-02 is a user-approved contract extension, not an unqualified claim
  that the old implementation violated that restriction. Preserve explicit
  retention settings, including raw=90/daily=365.
- Complete raw snapshot IDs determine liveness independently of tag parsing.
  Unknown attribution neither closes a tracked live connection nor invents usage.
- Fleet DB v5 normalizes existing/imported timestamps and rebuilds supported
  daily groups. audit-export/v2 identity/export_seq/pagination remain compatible.

## Migration and recovery

Preflight integrity, timestamps, schema and free space; use SQLite online backup
and verify it. Convert and verify a separate database before activation. Preserve
IDs, generations, sequences/cursors, and a snapshot of legacy daily rows. Never
add uncertain legacy aggregates to reconstructed totals. Report coverage and
unverifiable legacy history; previously deleted data remains unrecoverable.
No migrations in GET/read-only commands. Failure before activation leaves the
original intact. Before rollback after new writes, preserve the new database;
restoring an old snapshot is not described as lossless rollback.

## C — bounded cache and truthful failure

- Machine-local cache policy: max 8 GiB, warning at 80%, minimum free 512 MiB.
  Enforce SQLite page cap and reserve transaction/migration space. No automatic
  history deletion or silent limit increase; oversize existing databases stay RO.
- `cache status [--json]` is read-only, including for absent/old/corrupt databases.
- Normal sync, full sync and archive import share the guard. Errors use
  CACHE_LIMIT_REACHED / DISK_SPACE_LOW and PARTIAL exit 2, preserving committed
  pages and rolling back the refused page/cursor. Local errors do not damage
  remote-node health. Initial cache locking is also bounded and machine-readable.
- Backup verify and restore share required-member validation; stats missing or
  wrong databases fail nonzero without creating files.

## D — trustworthy checks and delivery

Allow empty valid short_id in diagnose. Fix journal collector root/import hints.
Platform/root prerequisites are explicit in tests; Linux required privilege tests
actually run. Existing-install checks use the canonical authentication negatives
and identity-consistency checker, rather than reporting positive-only success.
Update all schema readers, backup/restore, upgrade allowlists, package manifests,
fixtures, documentation/version tables. Run Windows/Ubuntu/Debian12/13, Bash/Fleet,
concurrency, injection, schemas and standalone artifact checks before RC freeze.
