## 边界与采集

Controller Inspect CLI/API仅查询machine-local缓存；GET、默认列表、UI、baseline预览不SSH。前台monitor以固定较低频率采集inspect/v1，通过observe路由；capability/telemetry/diagnostics/inspect/identity共用每Node总deadline，inspect失败不能丢弃有效telemetry。必须支持旧NodeUNSUPPORTED、observe AUTH_FAILED不fallback、重放/跨instance/时钟偏差UNKNOWN。

采集进入独立inspection.db，避免把最高64KiB的snapshot复制进每30秒telemetry raw/rollup和monitor/v1。公开monitor/v1字段保持严格合同；前台汇总若新增计数使用新schema后缀。使用有界SQLite事务、单独读连接mode=ro/query_only、容量/行数/锁等待/VM预算；坏行隔离，不由读取修复。

冻结上限：latest Node1024、baseline Node1024、DB128MiB；新目标超容量拒绝并显式CAPACITY，不驱逐已接受baseline。latest保留7天，baseline持续保留到显式替换或删除；容量不替代freshness。每个payload在读写两端完整validate，未知附加字段/秘密字段丢弃整行。读取不创建目录、DB、journal或baseline。

## 显式接受与CAS

冻结用户流程：缓存inspect列出snapshot摘要与canonical SHA；单独baseline接受命令必须提供该SHA。命令只操作本机缓存，不现场采集；事务内重新核对SHA、逻辑Node、当前instance、freshness与必要覆盖，防止预览后样本已变。重新接受必须显式，绝不由monitor或首次观察自动执行。

baseline source明确LOCAL_ACCEPTED，保留node/instance、source observed_at、accepted_at、accepted snapshot SHA、projection版本及比较对象。LOCAL_ACCEPTED只表示用户选择了比较参照；不是PENDING LIVE完成、代理测试PASS或Human Gate签署。Node replacement保留逻辑node_id但instance变化时旧baseline不适用，必须UNKNOWN并显式接受新instance。

冻结接受时必要完整分项：listeners、services、versions、fingerprints；数组未截断、16个固定fingerprint唯一且完整、两项service与版本齐全。动态CPU/memory/disk/update/NTP不进入desired指纹。缺必要覆盖拒绝接受；可选环境分项PARTIAL不阻止接受。完整性的最终合同用正反fixture冻结，不能把root PARTIAL一概当可接受。

## 比较与UNKNOWN转移

| 检查 | 比较范围 |
| --- | --- |
| listener | 规范TCP/UDP/family/address/zone/port集合；新增和缺失均有固定计数证据；不比较process argv |
| service | 两个受管unit的active/enabled、User/Group与nofile limits；restart count是动态观察，不进入desired baseline |
| version | VCL/installedVCL/经binary SHA验证的sing-box版本 |
| managed config | managed-config/v1 canonical non-secret SHA；秘密轮换不drift |
| unit/runtime/binary | 固定artifact SHA/mode/uid/gid；按固定name比较，不接受自由路径 |

每检查MATCH/DRIFT/UNKNOWN，整体任一DRIFT为DRIFT，无DRIFT但存在UNKNOWN为UNKNOWN，其余MATCH。分项失测不覆盖最后接受baseline。缺baseline、旧instance、stale、future skew、重放、缺工具/权限/截断/非法字段均UNKNOWN；UNKNOWN保留已ACTIVE Finding，完整MATCH才恢复。baseline重接受不冒充实际文件修复，Timeline独立记录其来源。

响应只含固定枚举、规范非秘密比较对象、hash、计数与时间；不回传完整secret配置、任意路径或stderr。Clash loopback与真实代理可用需由增强Verify的有效配置/实际probe证据判断；listener集合本身不能识别进程或证明数据面。

## Findings与合同兼容

新增Drift types及固定证据会超出现有findings/v1、timeline/v1的封闭enum/字段集合，须提供新schema后缀与fixture，不静默改写已冻结v1。共享Findings生命周期稳定id/去重/恢复/重开；缓存损坏、满盘、写失败和单Node失败隔离。CLI/UI消费新schema，同时保持历史v1文件与旧Node能力降级。

M2自动化覆盖：总deadline/低频调度、零SSH读API/CLI、首次不建baseline、SHA CAS并发、换instance、fresh/stale/replay与时钟偏差、缺项不假MATCH、真实文件drift/恢复/秘密轮换、坏缓存/秘密注入/锁/满盘/cap、混合Node、制品清单和独立ZIP。M1测试仅为底层collector证据，不能代替这些检查。

支持OS/VPS现场、人工listener/config/unit drift、真实代理前后对照与24h soak均PENDING LIVE；H05/H06/H07 PENDING HUMAN。依 [用户延期指令](../plans/MANUAL_VALIDATION_DEFERRED.md)跳过等待，继续实现，未实现项不能归为人工跳过。

## 实际命令与身份边界

`vcl-fleet inspect [NODE] --json`与`GET /api/inspect[?node=NODE]`读缓存；指定Node含snapshot，默认Fleet只含摘要。`baseline accept NODE --sha256 SNAPSHOT_SHA`与`baseline clear NODE --sha256 BASELINE_SHA`仅在本机操作，UI无接受动作。Monitor默认15秒总deadline、300秒Inspect cadence。当前身份要求≤90秒成功telemetry，Inspect≤600秒；接受时保持telemetry只读事务至基线CAS提交，baseline事件同事务。

基线内部baseline/v1保存原始已验证的脱敏source snapshot与SHA，比较投影运行时由固定COMPONENTS重新计算；不是可移植生产desired文档。PRIVATE DB拒绝坏行/未知字段/秘密注入，SQLite schema1。七类Drift使用findings/v2、baseline事件使用timeline/v2，完整旧v1合同保留；Findings物理schema2不变。
